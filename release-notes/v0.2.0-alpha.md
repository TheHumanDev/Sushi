# Sushi v0.2.0-alpha

## Overview

Sushi v0.2.0-alpha establishes the initial compiler analysis and language-server foundations for the Sushi programming language.

This release expands the original extension and publishing proof of concept into a workspace-aware development environment. It introduces source snapshots, lexical analysis, diagnostics, project and solution configuration processing, and the foundations for coordinating analysis across related documents.

**This is an early alpha release intended for development and experimentation.** It does not yet provide a complete Sushi compiler or executable code generation.

## Changes

### New Features

- **Source analysis foundation:** Introduced byte-oriented source snapshots, source spans, UTF-8 validation, and source coordinate conversion.
- **Lexical analysis:** Added initial lexer and tokenizer infrastructure, including line comments, nested block comments, and diagnostics for unterminated block comments.
- **Workspace-aware language server:** Added workspace document discovery, filesystem change handling, synchronized source snapshots, analysis scheduling, and LSP diagnostic publication.
- **Project and solution files:** Added `.susproj` and `.susln` document registration, TOML parsing, initial project configuration validation, and dedicated language definitions in the VS Code extension.
- **Project-aware analysis:** Added project source discovery using include and exclude patterns. The language server can associate tracked source documents with their projects when membership is unambiguous.
- **Command infrastructure:** Introduced a structured command system with dedicated compile, language-server, and help commands.

### Improvements

- Established `Sushi.Core` as a shared contract layer between the compiler and language server.
- Introduced `ISourceDocumentProvider` for extensible document-type registration and analysis dispatch.
- Separated workspace orchestration from analysis coordination.
- Added generation-aware analysis commitment to prevent stale results from replacing newer workspace state.
- Expanded diagnostic reporting and isolation between analysis operations.
- Added test coverage for source encoding, source spans, TOML parsing, project configuration, document registration, and workspace membership.
- Expanded language specification documentation covering source encoding, comments, and TOML configuration.

### Bug Fixes

- Corrected UTF-8 and UTF-16 source-coordinate handling and associated edge cases.
- Corrected extension normalization and document analysis updates.
- Addressed cancellation and resource-lifetime issues in workspace analysis scheduling.
- Corrected command argument parsing and error handling.
- Fixed project and solution analysis issues identified during development.

## Known Issues and Limitations

Many of the features of the compiler, including end-to-end compilation, is not implemented yet. Development is still in the scaffolding and architecture phase.

## Installation

Install [Sushi Language Support](https://marketplace.visualstudio.com/items?itemName=TheHumanDev.sushi-language) from the Visual Studio Code Marketplace and select the pre-release version.

Alternatively:

1. Download `sushi-language-win32-x64-0.2.0.vsix` from the GitHub release assets.
2. Open Visual Studio Code.
3. Open the Extensions view.
4. Select **Install from VSIX...** from the Extensions menu.
5. Select the downloaded VSIX file.

The extension requires a compatible version of Visual Studio Code as specified by its extension manifest.

## Artifact Verification

Each downloadable release artifact is accompanied by a SHA-256 checksum in `SHA256SUMS`.

To verify the integrity of the downloaded VSIX:

1. Download `sushi-language-win32-x64-0.2.0.vsix` and `SHA256SUMS`.
2. Place both files in the same directory.
3. Open PowerShell in that directory and run:

   ```powershell
   Get-FileHash .\sushi-language-win32-x64-0.2.0.vsix -Algorithm SHA256
   ```
4. Compare the resulting hash against the corresponding entry in `SHA256SUMS`.

The hashes must match exactly (case-insensitive). A mismatch indicates that the downloaded artifact differs from the file represented by the checksum manifest. Do not install an artifact with a mismatched checksum.

The checksum manifest provides an integrity check but does not independently establish the artifact's origin or build provenance.

**Build provenance attestations are not available for this release.** Future releases may include attestations allowing users to verify the source repository, commit, and build workflow associated with published artifacts.
